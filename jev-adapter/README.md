# Классификатор Jev для NIKA

Сервис принимает запрос `/message?q=...` от NIKA, вызывает Jev через OpenRouter Decisions API и преобразует выбор намерения и объекта в ту часть ответа Wit.ai, которую читает классификатор NIKA. Данные для ответа остаются в SC-графе, а правила и фразы — в NIKA. Jev здесь используется без обучения собственного приложения Wit.ai.

## Запуск

В корневом `.env` проекта должна быть строка `OPENROUTER_API_KEY=<ключ>`. Этот файл исключён из Git и Docker build context. Из каталога `nika`:

```powershell
docker compose -f docker-compose.yml -f docker-compose.lab.yml -f docker-compose.jev.yml up -d
```

В профиле сервиса сохранены имя `wit-mock` и адрес `http://wit-mock:8080/message`: это сетевой адрес, ожидаемый текущей конфигурацией NIKA, хотя контейнер с профилем Jev запускает этот адаптер. Чтобы переключить только запущенный классификатор, без пересборки памяти NIKA:

```powershell
docker compose -f docker-compose.yml -f docker-compose.lab.yml -f docker-compose.jev.yml up -d --no-deps --build wit-mock
```

Интерфейс: http://localhost:3033/?v=2. Состояние адаптера, выбранную модель и счётчики вызовов можно посмотреть без ключа:

```powershell
docker exec nika-wit-mock python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8080/health').read().decode())"
```

При запуске **без** `docker-compose.jev.yml` профиль использует локальный mock. Вернуться к нему, не меняя память NIKA:

```powershell
docker compose -f docker-compose.yml -f docker-compose.lab.yml up -d --no-deps --build wit-mock
```

Для Jev необходимы интернет и доступный ключ OpenRouter; каждый запрос тарифицируется по текущим условиям сервиса. Текст пользовательского сообщения отправляется OpenRouter. При ошибке API адаптер возвращает HTTP 502 и пустые классификации, не подменяя результат ответом локального mock. Клиентское поведение Ники при сбое зависит от её обработчиков.

Опционально в `.env` можно установить `JEV_MODEL` и `JEV_TIMEOUT_SECONDS`. Модель по умолчанию — `typesafe/jev-1.14`; порог вероятности по умолчанию не применяется, потому что он не откалиброван на независимой выборке.

## Ограничения и проверка

Передаётся один intent и одна сущность из ограниченного перечня `catalog.py`. Если Jev выбирает `unknown`, соответствующее поле остаётся пустым. Если Jev распознаёт несколько животных либо в сообщении найдены два разных животных в перечисленных в коде словоформах, сущность не подставляется: Ника выдаёт общий ответ об отсутствии сведений. Это ограниченная защита от ответа только об одном животном, а не полноценная поддержка нескольких сущностей; словарь покрывает не все словоформы. Для выбранной сущности используется русский идентификатор графа; позиции в исходном тексте не выдумываются, поскольку текущий C++ классификатор Ники их не читает.

```powershell
python -m unittest discover -s jev-adapter -p test_server.py -v
python reports/hunting/verify_jev_frontend.py
```

Вторая команда выполняет платные запросы через браузер, результаты сохраняет в `reports/hunting/jev_frontend_results.json`, скриншоты — в `reports/hunting/screenshots/jev/`. Эти проверки не являются обучением Wit.ai.
